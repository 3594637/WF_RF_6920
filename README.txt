==============================================================
rf_relay_6920  RF 接收转发工程  (MC30F6920, 33us 采样 + 200ms 休眠)
==============================================================

一、功能与引脚
--------------
  PT14  <- WF550RA 的 DO (接收数据, 输入)
  PT13  -> 转发输出 (有效帧期间跟随 PT14, 其余时间输出 0)
  PT15  -> 接收使能 (低=接收开/监听中, 高=接收关/休眠)
  PT10  -> 预留调试脚 (当前代码没有使用, 一直为高)

  8 脚封装:
    1 VDD   8 VSS
    2 PT15  7 PT10
    3 PT14  6 PT11
    4 PT13  5 PT12

  低功耗: 没有信号时每 200ms 醒一次, 监听约 6ms, 其余时间
          MCU 进 STOP、接收关断。

二、运行流程(状态机)
--------------------
  上电 -> Sys_Init() -> while(1) 状态机

  ST_LISTEN  (约 6ms)
      PT15=0 打开接收;
      先等 30 个 tick(约 1ms) 让接收输出稳定;
      再监听 150 个 tick(约 5ms), 每个 tick 调一次 IR_Rx_fun();
      期间 f_dataout 置 1 -> ST_FORWARD, 否则 -> ST_SLEEP。

  ST_FORWARD (按键按住期间一直停在这里)
      PT13 直通跟随 PT14;
      连续解码, 每识别一个合法 bit 都会刷新 activity 计时;
      超过 activity 时间没有新帧 -> f_dataout=0 -> 回 ST_SLEEP。

  ST_SLEEP   (200ms)
      PT13=0, PT15=1 关接收;
      关高频(HFEN=0), 执行 Stop();
      T0 约 200ms 溢出中断唤醒 -> Clk_High_Init() 恢复 8MHz
      -> 重配 T1 -> 回 ST_LISTEN。

  一个完整周期约 200ms(休眠) + 6ms(监听) ≈ 206ms。

三、时间基准
------------
  FCPU = 8MHz (烧录选项 FCPU = FOSC/2, FOSC 为 16MHz 高频 RC)

  T1: 33us 解码节拍
      T1CR   = 0x02   /* CPU 时钟 /8 = 1MHz */
      T1CNT  = 32
      T1LOAD = 32     /* 每 33 个 1MHz 周期中断一次 */
      T1IE   = 1      /* 中断里置 f_int_rx, 主循环做解码 */

  T0: 200ms 休眠定时
      时钟源 = FLIRC(内部低频 32kHz)
      T0CR   = 0x05   /* T0PRS=101 -> /64, 即 2ms 一个计数 */
      T0CNT  = 256-100 /* 100 个计数 = 200ms */

  WDT: 由烧录选项配置, 288ms, 只做看门狗兜底(见第五节)

四、解码参数(33us tick)
-----------------------
  LEVEL_TOUT = 64   单电平超过 64 tick(约 2.1ms) 判为帧间隙, 解码复位
  BIT_MIN    = 10   1bit 总宽下限, 约 330us
  BIT_MAX    = 80   1bit 总宽上限, 约 2.64ms
  VALID_BITS = 4    连续 4 个合法 bit 才算有效帧 (rx_test 是 5)

  判 1 / 判 0: 高电平宽度 >= 2 倍低电平 -> 1;
               低电平宽度 >= 2 倍高电平 -> 0;
               不满足(含高≈低) 一律当噪声, 丢弃整帧。
  一致性: 每个 bit 的总宽要和本帧第 1 个 bit 比, 相对容差 25%
          (最小 2 tick), 超差丢弃整帧。
  有效保持: 每识别一个合法 bit 刷新 activity = 首 bit 宽度 x 32 tick,
            中断里每个 33us 递减, 减到 0 就认为信号消失, f_dataout=0。
            按 1527 的 1ms 级位宽算, 松手后约 30~40ms 退出转发。

五、看门狗 WDT(重要)
--------------------
  WDT 完全由烧录选项决定, 软件里不做使能:
    - 烧录选项 WDT = 288ms, 始终开启(不能选"关闭")
    - 上电时 MCR.WDTEN 复位默认就是 1, 配置好就自动开始计数

  时钟与周期:
    T0CR.T0PTA = 0, 预分频器归 T0 使用, 所以 WDT 时钟是 1:1,
    溢出时间就是烧录选项里的 288ms(不受 T0 的 /64 影响)。

  运行中:
    WDT 溢出会复位芯片。手册要求清狗间隔小于溢出时间的 1/4,
    即 288ms 档要 72ms 内至少 ClrWdt() 一次。
    代码里各等待循环都带 ClrWdt(), 满足要求。

  休眠中:
    Stop() 会清零 WDT, 睡眠期间 WDT 继续计数, 溢出是唤醒 CPU
    (不是复位)。200ms < 288ms, 所以正常是 T0 先醒;
    醒来第一件事 ClrWdt(), 把 WDT 重新计满 288ms。

  高频起振失败:
    Clk_High_Init() 里等 STBH 超过 2000 次还不成功, 就不再喂狗,
    改由 WDT 复位恢复, 避免死等。

  !!! 坑: 如果 WDT 选项不是 288ms, 而是 72ms/18ms/4.5ms,
      休眠会被 WDT 提前打断, 实测周期变成 67ms/18ms/4.5ms 左右。
      这种情况下 T0 的 200ms 根本走不完, 必须把选项改回 288ms。

六、编译/烧录
-------------
  1. 用 Sinemcu IDE HID.exe 打开 rf_relay_6920.Proj
  2. 编译 -> Output\rf_relay_6920.s19
  3. SineMcuPro100S 烧录
  目录里必须有 Debug / Output / System 三个子文件夹(已建好)

七、烧录选项(重要)
------------------
  1. FCPU 分频 = FOSC/4   (本代码按 4MHz 写; 改 FCPU 必须同步改
     T1CR, 保证 T1 计数时钟还是 1MHz, 否则 33us 采样会变)
  2. P13 = 输入/输出脚    (绝不能选"P13 用作复位脚", 否则 PT13 输出不了)
  3. WDT = 288ms          (始终开启; 不是 288ms 就不能用 200ms 休眠)
  4. 加密 = 不加密        (调试阶段)

八、上电验证 / 排查
------------------
  1. 先确认烧录选项: WDT=288ms、P13 不是复位脚、FCPU=FOSC/2。
     只看"编译成功"不够, 要看到烧录器提示成功, 可用"读取"回读校验。
  2. PT15 平时为高, 每 206ms 左右拉低约 6ms(监听窗口)。
     逻辑分析仪看到约 206ms 周期 -> 休眠正常。
     看到约 67ms -> WDT 选项还是 72ms 档, 不是代码问题。
  3. 按遥控器: PT15 变低, PT13 跟随 PT14 翻转;
     松手后约 30~40ms PT13 回 0, 再睡 200ms。
  4. PT10 目前没有输出(调试脚预留), 不要拿它判断程序是否在跑。
  5. 芯片供电 2.2~5.5V; 逻辑分析仪 GND 必须和板子共地。
  6. 烧录排线测试时最好拔掉(烧录脚可能钳住 IO)。


九、注意
--------
  1. 源码 main.c 是 GBK 编码; user.h / README 是 UTF-8。
     IDE 里中文注释显示乱码只是编码显示问题, 不影响编译。
  2. PT13 是"透明直通", 有效帧期间始终跟随 PT14。
     若要"仅在有效时转发", 把
         io_OUT = io_rfdata;
     改成
         io_OUT = f_dataout ? 1 : 0;     // 按你的极性
  3. WDT 选项改成"关闭"程序也能跑: 功能不变, 但没有复位兜底,
     Stop() 之后也只有 T0 能唤醒, 调试时不会被打断。
  4. 本工程不做"低功耗"以外的电源管理: 休眠靠 STOP + 关接收,
     WF550RA 关断后的电流决定整机休眠电流。
